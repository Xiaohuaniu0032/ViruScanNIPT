# Output formats

Sample-level and cohort Summary tables are tab-delimited text. The sample-level raw BLAST table uses the `.xls` suffix for historical convenience; it is **not** an Excel workbook.

## 1. Sample-level output files

### `<sample>_blast_raw_result.xls`

Written by `bin/parseBlast.pl`. Despite the `.xls` suffix, this is a TSV file with the following columns:

| Column | Meaning |
|---|---|
| `query` | FASTA query/read identifier passed to BLASTN. |
| `subject` | BLAST subject accession, retaining its version suffix when present. |
| `identity` | Percent sequence identity. |
| `alignment_length` | Length of the aligned region in bases. |
| `mismatches` | Number of mismatched positions. |
| `gap_opens` | Number of gap openings. |
| `q.start`, `q.end` | Query alignment coordinates. |
| `s.start`, `s.end` | Subject alignment coordinates. |
| `evalue` | BLAST expect value. |
| `bit_score` | BLAST bit score. |

This table includes subject accessions beginning with `NC_`, `AC_` or `NG_` before the identity, alignment-length and e-value cutoffs are applied.

### `<sample>_blast_out_parsed.txt`

Written by `bin/parseBlast.pl`. This is the normalized table consumed by the cohort Summary script.

| Column | Meaning |
|---|---|
| `sample` | Sample identifier. |
| `query` | Query/read identifier. |
| `subject` | Selected RefSeq-style subject accession with the version suffix removed. |
| `identity` | Percent sequence identity. |
| `alignment_length` | Alignment length in bases. |
| `evalue` | BLAST expect value. |
| `viral_name` | Organism name looked up from `locusOrganism.tsv`, or `NA` if no accession mapping is found. |

The parser applies the configured identity, alignment-length and e-value cutoffs and retains one qualifying subject hit per query according to the BLAST output order. The table is written with a header even when no query passes the filters.

### Other sample-level files

| File pattern | Purpose |
|---|---|
| `<sample>.run.sh` | Executable sample workflow shell generated by the main program. |
| `<sample>.blast.out` | BLASTN outfmt 7 output before parsing. |
| `<sample>.bwa.log`, `<sample>.samtools.log`, `<sample>.blast.log`, `<sample>.parseBlast.log` | Per-step logs. |
| `<sample>.sam`, `<sample>.bam`, `<sample>.sort.bam`, `<sample>.sort.bam.bai` | Alignment intermediates; retention depends on `KEEP_INTERMEDIATE`. |
| `<sample>.unmapped.bam`, `<sample>.unmapped.fa` | Reads not aligned to the human reference; retained in both `KEEP_INTERMEDIATE` modes. |

## 2. Cohort Summary output files

All Summary files are tab-delimited text (TSV). The output directory is created by `bin/summarizeGroupnameResults.pl`.

The counting unit is a **distinct query identifier per sample per Groupname**. A query that has multiple BLAST subject accessions assigned to the same Groupname is counted once in that sample and Groupname.

## 1. `sampleGroupCounts.tsv`

One row for every sample × Groupname combination represented by the input parsed files and the Groupname annotation table. Zero-count combinations are retained.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier from the parsed `sample` column, or inferred from the parsed filename when the file contains only a header. |
| `Groupname` | Curated Groupname label from `viralGroupname.tsv`. |
| `DistinctQueryCount` | Number of unique query identifiers assigned to this Groupname in this sample. |
| `Status` | `Positive` when `DistinctQueryCount` is greater than or equal to the configured cutoff; otherwise `Negative`. |

## 3. `sampleSummary.tsv`

One row per sample.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier. |
| `TotalDistinctAssignedQueries` | Number of unique query identifiers assigned to any valid Groupname in the sample. A query assigned to two different Groupnames contributes once to each Groupname but once to this sample-level union. |
| `GroupnamesWithAtLeastOneRead` | Number of Groupnames with at least one assigned query. |
| `PositiveGroupCount` | Number of Groupnames meeting the positive cutoff. |
| `PositiveGroupnames` | Semicolon-delimited positive Groupname labels, or `NA` if none. |

## 4. `groupSummary.tsv`

One row per Groupname in the annotation table.

| Column | Meaning |
|---|---|
| `Groupname` | Curated Groupname label. |
| `PositiveSampleCount` | Number of samples meeting the positive cutoff for this Groupname. |
| `TotalSampleCount` | Number of unique samples represented by parsed files. |
| `PositiveRatePercent` | `PositiveSampleCount / TotalSampleCount × 100`. |
| `TotalDistinctQueries` | Sum of per-sample distinct query counts for this Groupname across the cohort. This is a sum of sample-level counts, not a cohort-wide unique-query count. |
| `MeanReadsPerPositiveSample` | Arithmetic mean of distinct query counts among positive samples only. |
| `MedianReadsPerPositiveSample` | Median distinct query count among positive samples only. |
| `Q1`, `Q3` | First and third quartiles among positive samples only, calculated by linear interpolation at positions `(n - 1) × p`. |
| `Min`, `Max` | Minimum and maximum distinct query counts among positive samples only. |

When no sample is positive for a Groupname, the positive-sample distribution fields are `NA`.

## 5. `groupReadCounts.tsv`

One row per positive sample × Groupname combination.

| Column | Meaning |
|---|---|
| `Groupname` | Curated Groupname label. |
| `Sample` | Sample identifier. |
| `DistinctQueryCount` | Number of unique query identifiers assigned to this Groupname in this sample. |

This table contains positive combinations only. It is intended for downstream analysis and visualization.

## 6. `groupCoDetection.tsv`

One row per observed pair of positive Groupnames.

| Column | Meaning |
|---|---|
| `Groupname1`, `Groupname2` | Alphabetically ordered pair of Groupname labels. |
| `CoDetectedSamples` | Number of samples positive for both Groupnames. |
| `CohortPercent` | `CoDetectedSamples / TotalSampleCount × 100`. |

A sample positive for three or more Groupnames contributes to every pairwise combination among its positive Groupnames. Therefore, pairwise co-detection counts are not mutually exclusive.

## 7. `sampleCoDetection.tsv`

One row per sample with at least two positive Groupnames.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier. |
| `PositiveGroupCount` | Number of positive Groupnames in the sample. |
| `CoDetectionCombination` | Alphabetically sorted positive Groupname labels joined by ` + `. |

Samples with zero or one positive Groupname are not included.

## 8. `groupCombinationSummary.tsv`

One row per exact multi-Groupname combination.

| Column | Meaning |
|---|---|
| `CoDetectionCombination` | Exact alphabetically sorted Groupname combination. |
| `PositiveSampleCount` | Number of samples with exactly this combination of positive Groupnames. |

Unlike `groupCoDetection.tsv`, this table counts exact combinations. A sample with three positive Groupnames contributes one three-Groupname combination here, but contributes three pairwise combinations to `groupCoDetection.tsv`.

## 9. `unmappedAccessions.tsv`

Accession-level quality-control output for parsed BLAST subjects not found in `viralGroupname.tsv`.

| Column | Meaning |
|---|---|
| `ACCESSION` | Versionless accession extracted from the parsed `subject` column. |
| `UnmappedRecordCount` | Number of parsed records with this accession that were not mapped to a Groupname. |
| `DistinctSampleQueryPairs` | Number of unique sample × query pairs associated with this accession. |

This is an annotation quality-control table. An unmapped accession is not, by itself, evidence of a positive or negative clinical result.

## 10. `summary.log`

A text log recording the input path, Groupname table, positive cutoff, number of parsed files and samples, parsed/mapped/unmapped records, phage-filtered records, Groupname count and output directory.

## Counting and filtering rules

1. `query` is the read-level identifier and is the unit counted by Summary.
2. Accession version suffixes such as `.1` and `.2` are removed before matching to the Groupname table.
3. Each query is counted once per sample per Groupname, even if duplicate parsed rows or multiple subject accessions within that Groupname are present.
4. The positive cutoff is inclusive: a sample is positive when its distinct query count is `>= POSITIVE_HIT_CUTOFF`.
5. A sample may be positive for multiple Groupnames; Groupname-specific counts and percentages are not mutually exclusive.
6. The cohort denominator is the number of unique sample IDs represented by the parsed files supplied to Summary. Header-only parsed files are included as samples.
7. Rows whose `viral_name` contains `phage` are excluded.
8. Rows whose accession is absent from the Groupname table, or whose Groupname value is blank, `NA` or `N/A`, are not assigned to a Groupname. Unmapped accessions are reported separately.
9. When multiple parsed files contain the same sample ID, their records are combined before distinct query counting.
