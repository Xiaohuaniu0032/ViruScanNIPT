# Output formats

Sample-level and cohort-level result tables are tab-delimited text files
(TSV). The sample-level raw BLAST table uses the `.xls` suffix for historical
reasons, but it is **not an Excel workbook**.

## 1. Sample-level output files

### 1.1. `<sample>_blast_raw_result.xls`

This file is written by `bin/parseBlast.pl`. Despite its suffix, it is a TSV
file containing BLAST alignment fields.

| Column | Meaning |
|---|---|
| `query` | FASTA query or read identifier passed to BLASTN. |
| `subject` | BLAST subject accession, including its version suffix when present. |
| `identity` | Percent sequence identity. |
| `alignment_length` | Length of the aligned region in bases. |
| `mismatches` | Number of mismatched positions. |
| `gap_opens` | Number of gap openings. |
| `q.start`, `q.end` | Query alignment coordinates. |
| `s.start`, `s.end` | Subject alignment coordinates. |
| `evalue` | BLAST expect value. |
| `bit_score` | BLAST bit score. |

This file includes subject accessions beginning with `NC_`, `AC_` or `NG_`.
The identity, alignment-length and e-value filters are applied later by the
parser.

### 1.2. `<sample>_blast_out_parsed.txt`

This file is written by `bin/parseBlast.pl` and is the input to the cohort
Summary program.

| Column | Meaning |
|---|---|
| `sample` | Sample identifier. |
| `query` | Query or read identifier. |
| `subject` | Selected RefSeq-style subject accession with the version suffix removed. |
| `identity` | Percent sequence identity. |
| `alignment_length` | Alignment length in bases. |
| `evalue` | BLAST expect value. |
| `viral_name` | Organism name looked up from `locusOrganism.tsv`, or `NA` when no mapping is found. |

The parser applies the configured identity, alignment-length and e-value
cutoffs. It retains one qualifying subject hit per query according to the
record order in the BLAST output. A header is written even when no query
passes the filters.

### 1.3. Other sample-level files

| File pattern | Purpose |
|---|---|
| `<sample>.run.sh` | Executable sample workflow shell generated by the main program. |
| `<sample>.blast.out` | BLASTN outfmt 7 output before parsing. |
| `<sample>.bwa.log` | BWA log. |
| `<sample>.samtools.log` | SAMtools log. |
| `<sample>.blast.log` | BLASTN log. |
| `<sample>.parseBlast.log` | Parser log. |
| `<sample>.sam`, `<sample>.bam`, `<sample>.sort.bam`, `<sample>.sort.bam.bai` | Alignment intermediates controlled by `KEEP_INTERMEDIATE`. |
| `<sample>.unmapped.bam`, `<sample>.unmapped.fa` | Reads that did not align to the human reference. These files are retained in both `KEEP_INTERMEDIATE` modes. |

## 2. Cohort Summary output files

All files in the Summary output directory are TSV files. The directory is
created by `bin/summarizeGroupnameResults.pl`.

### Counting unit

The primary counting unit is one **distinct query identifier per sample per
Groupname**. If one query has multiple subject accessions assigned to the
same Groupname, that query is counted once for that sample and Groupname.

The positive definition is inclusive:

```text
DistinctQueryCount >= POSITIVE_HIT_CUTOFF
```

The default cutoff is 2. A sample can be positive for more than one
Groupname.

### 2.1. `sampleGroupCounts.tsv`

This is the sample-by-Groupname count table. It contains one row for every
combination of sample and Groupname represented by the parsed files and the
Groupname annotation table. Combinations with zero counts are retained.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier from the parsed `sample` column. For a header-only file, it is inferred from the filename. |
| `Groupname` | Curated Groupname label from `viralGroupname.tsv`. |
| `DistinctQueryCount` | Number of distinct query identifiers assigned to this Groupname in this sample. |
| `Status` | `Positive` when the count meets or exceeds the configured cutoff. Otherwise `Negative`. |

### 2.2. `sampleSummary.tsv`

This file contains one row per sample.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier. |
| `TotalDistinctAssignedQueries` | Number of distinct query identifiers assigned to any valid Groupname in the sample. A query assigned to different Groupnames contributes once to each Groupname, but only once to this sample-level union. |
| `GroupnamesWithAtLeastOneRead` | Number of Groupnames with at least one assigned query. |
| `PositiveGroupCount` | Number of Groupnames meeting the positive cutoff. |
| `PositiveGroupnames` | Positive Groupname labels in alphabetical order, separated by semicolons. `NA` is written when there are no positive Groupnames. |

### 2.3. `groupSummary.tsv`

This file contains one row for each Groupname in the annotation table.

| Column | Meaning |
|---|---|
| `Groupname` | Curated Groupname label. |
| `PositiveSampleCount` | Number of samples meeting the positive cutoff for this Groupname. |
| `TotalSampleCount` | Number of unique samples represented by the parsed files. |
| `PositiveRatePercent` | `PositiveSampleCount / TotalSampleCount × 100`. |
| `TotalDistinctQueries` | Sum of sample-level distinct query counts for this Groupname across the cohort. This is not a cohort-wide unique-query count. |
| `MeanReadsPerPositiveSample` | Arithmetic mean of distinct query counts among positive samples only. |
| `MedianReadsPerPositiveSample` | Median distinct query count among positive samples only. |
| `Q1`, `Q3` | First and third quartiles among positive samples, calculated by linear interpolation at positions `(n - 1) × p`. |
| `Min`, `Max` | Minimum and maximum distinct query counts among positive samples. |

When no sample is positive for a Groupname, the positive-sample distribution
fields are reported as `NA`.

### 2.4. `groupReadCounts.tsv`

This file contains one row for each positive sample-by-Groupname combination.

| Column | Meaning |
|---|---|
| `Groupname` | Curated Groupname label. |
| `Sample` | Sample identifier. |
| `DistinctQueryCount` | Number of distinct query identifiers assigned to this Groupname in this sample. |

Only combinations meeting the positive cutoff are included. This table is
intended for downstream statistical analysis and visualization.

### 2.5. `groupCoDetection.tsv`

This file reports observed pairs of positive Groupnames.

| Column | Meaning |
|---|---|
| `Groupname1`, `Groupname2` | Alphabetically ordered pair of Groupname labels. |
| `CoDetectedSamples` | Number of samples positive for both Groupnames. |
| `CohortPercent` | `CoDetectedSamples / TotalSampleCount × 100`. |

Only pairs detected in at least one sample are written. A sample positive for
three or more Groupnames contributes to every pairwise combination among
those positive Groupnames. Pairwise counts are therefore not mutually
exclusive.

### 2.6. `sampleCoDetection.tsv`

This file contains one row for each sample with at least two positive
Groupnames.

| Column | Meaning |
|---|---|
| `Sample` | Sample identifier. |
| `PositiveGroupCount` | Number of positive Groupnames in the sample. |
| `CoDetectionCombination` | Alphabetically sorted positive Groupname labels joined by ` + `. |

Samples with zero or one positive Groupname are not included.

### 2.7. `groupCombinationSummary.tsv`

This file summarizes exact combinations of multiple positive Groupnames.

| Column | Meaning |
|---|---|
| `CoDetectionCombination` | Exact combination of positive Groupnames, sorted alphabetically and joined by ` + `. |
| `PositiveSampleCount` | Number of samples with exactly this combination. |

This table differs from `groupCoDetection.tsv`. A sample with three positive
Groupnames contributes one exact three-Groupname combination here, but
contributes three pairwise combinations to `groupCoDetection.tsv`.

### 2.8. `unmappedAccessions.tsv`

This is an accession-level quality-control table for parsed BLAST subjects
that cannot be matched to `viralGroupname.tsv`.

| Column | Meaning |
|---|---|
| `ACCESSION` | Version-normalized accession extracted from the parsed `subject` column. |
| `UnmappedRecordCount` | Number of parsed records with this accession that were not mapped to a Groupname. |
| `DistinctSampleQueryPairs` | Number of unique sample and query pairs associated with this accession. |

An unmapped accession is not, by itself, evidence of a positive or negative
clinical result. Review these records when updating the Groupname annotation
table or the viral reference database.

### 2.9. `summary.log`

The log records the input path, Groupname table, positive cutoff, number of
parsed files and samples, parsed and mapped record counts, unmapped records,
phage-filtered records, number of Groupnames and output directory.

## 3. Counting and filtering rules

1. `query` is the read-level identifier and the unit counted by Summary.
2. Accession version suffixes such as `.1` and `.2` are removed before
   matching parsed `subject` values to `ACCESSION` in the Groupname table.
3. Each query is counted once per sample per Groupname, even when duplicate
   parsed rows or multiple subject accessions within that Groupname are present.
4. The positive cutoff is inclusive. A sample is positive when its distinct
   query count is greater than or equal to `POSITIVE_HIT_CUTOFF`.
5. A sample may be positive for multiple Groupnames. Groupname-specific
   counts and percentages are not mutually exclusive.
6. The cohort denominator is the number of unique sample IDs represented by
   the parsed files supplied to Summary. Header-only parsed files are included.
7. Parsed rows whose `viral_name` contains `phage`, ignoring letter case, are
   excluded before Groupname assignment.
8. Accessions absent from the Groupname table are not assigned to a
   Groupname. They are reported separately in `unmappedAccessions.tsv`.
9. Multiple parsed files with the same sample ID are combined before
   distinct-query counting.
10. Groupname-specific query counts are based on distinct queries within each
    sample and Groupname. The same query can contribute to different
    Groupnames if its records map to different Groupname labels.

## 4. Interpretation

The positive status in these files is defined by a configurable read-count
threshold. It is intended for research screening and does not establish
infection or a clinical diagnosis. Review the underlying read evidence,
controls, database composition and clinical context before interpretation.
